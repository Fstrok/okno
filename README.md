# Okno

Linux-компьютер с рабочим столом (Debian 13 + XFCE) прямо в Android-телефоне, без root.
Цель: рабочая среда для кодинга на телефоне, с сетью через Wi‑Fi и мобильный интернет.

**Главный принцип:** пользователь не вводит команд. Первый запуск — одна кнопка «Установить»,
после неё сразу рабочий стол. Каждый следующий запуск — сразу рабочий стол.

## Установка

1. Скачай APK: **Releases → dev** (всегда свежая сборка из `main`) или артефакт `okno-apk` в Actions.
2. Установи (разреши установку из этого источника).
3. Открой Okno и нажми **«Установить»**. Через пару минут откроется рабочий стол.

Новые сборки ставятся поверх старых, установленная система при этом сохраняется.

## Что умеет сейчас

- **Рабочий стол XFCE** на русском: панель задач внизу, меню «Пуск», проводник Thunar, терминал, текстовый редактор.
- **Управление касаниями**: тап — клик, двойной тап — двойной клик, перетаскивание — перетаскивание,
  долгое нажатие — правая кнопка, два пальца вверх/вниз — прокрутка, щипок — масштаб.
- **Сделано под телефон**: рабочий стол не заходит под скруглённые углы экрана и вырез камеры (касание в чёрной
  полоске попадает в край рабочего стола — кнопка «закрыть» в углу нажимается); окна нельзя утащить за край —
  после отпускания они возвращаются в экран; большие окна сразу открываются развёрнутыми; крупные кнопки у окон;
  файлы и папки открываются одним касанием.
- **Клавиатура**: кнопка ⌨, русский и английский ввод; панель с ESC, TAB, CTRL, ALT, WIN, стрелками, DEL, F1–F12.
  Физические клавиатура и мышь тоже работают.
- **Поворот экрана**: разрешение рабочего стола подстраивается под ориентацию.
- **Debian 13 (trixie) arm64**, `apt` работает: `apt install git python3 nodejs build-essential …`
- **Сеть**: Wi‑Fi, мобильный интернет и VPN. DNS берётся из текущей сети Android и обновляется при переключении.
- **Работа в фоне**: уведомление держит Linux живым; «Не засыпать» удерживает процессор и Wi‑Fi при выключенном экране.
- **Общий буфер обмена**: скопировал в Linux (Ctrl+C) — вставляй в Android, и наоборот; русский текст тоже.
- **Браузер Chromium** — первым в меню «Пуск» и браузер по умолчанию; при первом запуске сам скачивается (~1–2 минуты).
  Google Chrome под Linux на ARM не выпускается, Chromium — та же основа.
- **Claude Code**: в меню «Пуск» или командой `claude` в терминале; при первом запуске ставится официальным
  установщиком (~90 МБ) и дальше обновляется сам.
- **Windows-программы** (.exe, 32 и 64 бит): двойное касание по .exe в проводнике — при первом запуске
  сама ставится поддержка (около 290 МБ загрузки). Внутри — [Hangover](https://github.com/AndreRH/hangover):
  сам Wine работает нативно на ARM64, эмулируется только код программы — 64-битный через FEX (ARM64EC),
  32-битный через Box64. Это быстрее, чем Wine целиком под эмулятором. Настройки скорости —
  `/etc/okno/windows.env`; в меню «Пуск» — «Настройки Windows» и «Проводник Windows».
- **Программы в один тап** (☰ → «Программы…»): Windows-программы, Claude Code, VS Code, Firefox, Chromium, Python,
  Node.js, Git, gcc/cmake, Java, Geany.
- **Тест графики** (☰ → «Тест графики» или в меню «Пуск»): процессор, память, накладные расходы proot, доступ к
  видеочипу Adreno из Linux, скорость отрисовки рабочего стола. Отчёт сохраняется в «Загрузки/okno-test.txt».
- **Удалённый доступ** (☰ → «Удалённый доступ (SSH)»): терминал по SSH и файлы по SFTP с компьютера в той же Wi‑Fi;
  пароль генерируется на телефоне, ключи сервера создаются на каждом телефоне свои.
- **Файлы телефона** в проводнике: папка «Телефон» (/sdcard), доступ спрашивается сразу после установки.
- **Размер интерфейса** (☰ → «Размер интерфейса…»): крупный / обычный / мелкий, меняется на лету.
- **Обновление системы**: если в новой версии APK обновлён Linux, приложение предложит переустановить систему.
- **Терминал Android** (☰ → «Терминал») — запасной вход, если рабочий стол не нужен.

Меню ☰ (слева на панели клавиш): программы, терминал, тест графики, перезапуск рабочего стола, размер интерфейса,
файлы телефона, сеть, SSH, сон, батарея, выход.

### Чего нет и почему

- **Steam и 3D-игры**: рабочий стол пока рисуется без видеочипа, 3D считается процессором (llvmpipe).
  Windows-версию Steam можно пробовать через Windows-программы, но для игр нужен видеочип — следующий шаг
  после теста графики (драйвер Turnip + Zink/DXVK). Сейчас для игр — Winlator/GameNative или Steam Link.

### Если система убивает процессы

vivo/iQOO и Android 12+ ограничивают фоновые процессы:
- ☰ → «Не ограничивать в фоне» (отключает оптимизацию батареи для Okno);
- Android 14+: «Для разработчиков» → «Отключить ограничения дочерних процессов».

## Как устроено

```
Android-приложение (Kotlin)
 ├─ DesktopActivity  — главный экран: кнопка «Установить», затем рабочий стол
 │   └─ DesktopView + RfbClient — показ рабочего стола (VNC через приватный Unix-сокет), касания → мышь, ввод → клавиши
 ├─ TerminalActivity — терминал (библиотека Termux terminal-view) + панель клавиш
 ├─ LinuxService     — foreground-сервис: процесс рабочего стола, терминальные сессии, wake/wifi lock
 ├─ NetworkConfig    — DNS из активной сети Android → /etc/resolv.conf
 ├─ RootfsInstaller  — распаковка системы из assets
 └─ LinuxEnvironment — команда запуска proot
        │
        ▼
proot (lib/arm64-v8a/libproot.so) — подменяет корень ФС и root-пользователя через ptrace
        │
        ▼
Debian 13 arm64 (files/rootfs)
 └─ okno-desktop: Xvnc :1 (сокет /tmp/.okno/vnc.sock) + XFCE
```

Сокет рабочего стола лежит в приватной папке приложения, поэтому другие приложения на телефоне подключиться к нему не могут.

- **Окна** (`native/wm-guard.c`): после перетаскивания возвращает окно в экран, большие новые окна разворачивает —
  всё запросами к оконному менеджеру (EWMH), так что xfwm4 остаётся главным.
- **Видеочип**: в Android он доступен не через `/dev/dri`, а через драйвер Qualcomm KGSL (`/dev/kgsl-3d0`).
  `native/gpu-probe.c` проверяет, может ли Linux-процесс сделать то же, что драйвер Mesa Turnip: опросить чип,
  создать контекст, выделить память. От этого зависит, можно ли подключить Vulkan/OpenGL на видеочипе.
- **SFTP под proot**: proot запрещает `prctl(PR_SET_DUMPABLE)`, без которого sftp-server не стартует;
  прослойка `native/nodumpable.c` (LD_PRELOAD только для SFTP) отвечает «успешно».
- **proot** и его библиотеки взяты из пакетов Termux (`scripts/update-proot.sh`, версии в `scripts/proot-sources.txt`) и лежат в репозитории как `jniLibs`: Android разрешает запускать бинарники только оттуда.
- **Система**: официальный образ `debian:trixie-slim` (arm64, закреплён по sha256 в `scripts/fetch-rootfs.sh`)
  плюс XFCE, TigerVNC и настройки из `rootfs-overlay/` — всё собирает `scripts/build-rootfs.sh`.
  В git образ не хранится; CI собирает его под qemu и кэширует, пока рецепт не изменится.
- `targetSdk 28`, как у Termux: более новые target запрещают `exec()` файлов из данных приложения, а Linux на этом построен.

## Сборка

```bash
sudo apt install qemu-user-static gtk-update-icon-cache libtalloc-dev uthash-dev gcc-aarch64-linux-gnu libx11-dev   # qemu нужен только на x86_64
scripts/build-proot.sh /tmp/proot         # proot со statx (в пакетах дистрибутивов старый 5.1.0)
sudo env PROOT=/tmp/proot/proot scripts/build-rootfs.sh   # Debian + XFCE → app/src/main/assets/rootfs.tgz
./gradlew assembleDebug                   # → app/build/outputs/apk/debug/app-debug.apk
```

Нужны JDK 17+ и Android SDK (`local.properties` → `sdk.dir=...`). GitHub Actions собирает APK на каждый пуш в `main` и выкладывает его в релиз `dev`.

APK подписан отладочным ключом из репозитория (`app/okno-debug.keystore`), чтобы все сборки ставились друг поверх друга.

## Лицензии компонентов

proot (GPL-2.0), talloc (LGPL-3.0), libandroid-shmem (BSD), Termux terminal-view/terminal-emulator (Apache-2.0), Debian, XFCE, TigerVNC (свободные лицензии пакетов).
